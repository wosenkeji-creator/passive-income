## 分发渠道
- 渠道：Apify Store
- 自然发现流量来源：Apify Store 站内搜索 + 平台自带买家池。**不需要自己宣传**，这是选它的唯一理由。
- 抽成 / 费用：平台抽 **20%**，且**平台成本（计算单元 + 代理流量）从开发者这侧扣**
  官方公式：`profit = (0.8 × revenue) − costs`
- 免费窗口：Creator Plan 约 $1/月，含约 $500 平台用量额度，**仅限前 6 个月**
  → 这个 6 个月天然就是验证期限，和「G2 后 90 天」对得上
- 计费模式：**按次计费（pay-per-event / pay-per-result）**，用户跑一次付一次
- 政策风险：中低。主要风险是平台调整分成或计费模型，非账号级封禁风险。

> 选它的三个结构性理由：
> 1. 代码在平台上跑 → **盗版不了**
> 2. 平台代收费、代导流 → 不用建收款也不用做营销
> 3. 同一份逻辑可复用成 p13 付费 MCP Server → 一次开发两个入口

### 代理成本决定可行性（不是优化问题）
平台代理 Starter 计划 **$8/GB**。按每条结果约 200KB 估，纯代理成本约 **$0.0016/条**。

| 定价 | 代理占分成比例 | 结论 |
|---|---|---|
| $0.01/条 | ~20% | 加上算力仍有毛利 |
| $0.001/条 | **>100%** | 做多少亏多少 |

→ **需要住宅代理 + 需要完整浏览器渲染的目标，在按次计费下不可行。** 选题必须排除。

参考基线（调研所得，独立可验证）：新 Actor 三个月做到约 64 用户 / 约 $200 一个月；
头部独立开发者 >$10k MRR。**中位数远低于此，按 $200 规划，不按 $10k 规划。**

## 最危险假设
**假设：Apify Store 站内搜索能带来真实的自然发现流量，不需要自己做营销。**

这是 p01 排第 1 的唯一依据。如果 Store 只是个"已知 URL 的托管页"而不是"买家会主动搜索的市场"，
那 p01 就退化成"自建落地页 + 自己拉流量"，被动性归零，排名作废。

- 最便宜的伪证动作：查 Apify Store 的搜索功能实际表现 + 第三方（非 Apify 自己）关于 Store 流量的证据
- 判定时限：立项前（即现在，调研中）
- 伪证后的动作：宣布 p01 排名作废，在 `DECISION_LOG.md` 标 D-001 `REVOKED`，换下一名

## 放弃条件
- G2 后 **90 天**内没拿到 G3（陌生人首笔付款）→ 杀掉，不续命

## 维护面
- 必须介入的情况：目标站点改版 / 反爬升级 / 平台 SDK breaking change
- 预计月维护：2–4 小时
- 这个维护量是**纯负担，不是护城河**。

> 修正记录（2026-08-09）：先前写过"维护量是护城河，目标站改版会淘汰不维护的竞争者"。**撤回。**
> 该说法会诱导选题往难维护的目标走，方向是错的。护城河在**按次计费不可盗版 + Store 排位 + 先到者优势**，
> 与维护量无关。选题应优先选**低维护**目标（受外部标准约束的数据出口，格式不因设计改版而变）。

### 提取层的工程要求
- 绑**语义锚点**（JSON-LD 字段名、schema.org 属性、API 字段名），**不绑 CSS 选择器**。
  这一条对维护频率的影响可能大于其他所有因素之和。
- 失败告警必须能区分两种情况：**结构变更**（站点改版，改解析）vs **反爬拦截**（被封，改策略）。
  混在一起会导致每次告警都要人工判断，直接破坏被动性。
